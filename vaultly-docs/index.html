1. Quick start

Upload

Select Upload documents or drag files into the browser.

Process

Vaultly extracts text, runs OCR when necessary, and creates a searchable record.

Review

Check the title, date, correspondent, type, tags, and extracted content.

Retrieve

Search for words inside the file or filter by structured metadata.

Recommended first document

  1. Upload a non-sensitive sample invoice.
  2. Wait until processing finishes.
  3. Open it and check the Content tab.
  4. Add a correspondent, document type, and tag.
  5. Search for a unique phrase from the invoice.
Example: Upload “Acme Office Supplies Invoice 1048.pdf.” Set Correspondent to “Acme Office Supplies,” Type to “Invoice,” and Tag to “Accounts Payable.” Searching for “1048” should return it.

3. Documents

A Vaultly document is more than the original file. It combines the file, searchable content, metadata, permissions, processing history, and optional notes.

Uploading

Use the dashboard upload button or drag and drop. Vaultly accepts common PDFs, images, and office formats supported by the deployment. Multiple files may be uploaded together.

Do not upload password-protected files unless your workflow is prepared to handle them. Encryption may prevent content extraction.

Document details

Editing safely

Select Save to remain on the document or Save & close to return to the list. Avoid changing metadata merely to test a setting on an important record.

4. OCR and extracted content

OCR converts visible text in scans and photographs into machine-readable content. Documents that already contain embedded text may only need extraction.

What affects OCR quality

  • Correct OCR language configuration.
  • Straight, well-lit pages with readable contrast.
  • Adequate resolution without excessive compression.
  • Minimal handwriting, shadows, folds, and background patterns.
Example: A scanned receipt contains “Silver Elephant 926.” After processing, that phrase appears under Content and can be found from the global search bar.

When OCR is wrong

Confirm the configured languages, rescan the page more clearly, or correct the indexed Content if your permissions allow it. Keep the original file as the authoritative visual record.

5. Search and filters

Full-text search finds words inside documents. Filters narrow results using structured fields. Combining both is usually the fastest approach.

MethodUse it forExample
Simple text searchKnown names, phrases, or reference numbers.Silver Elephant 926
Correspondent filterEverything associated with one organization.All records from “Acme Supplies.”
Document type filterA business category.Only Contracts.
Tag filterStatus or cross-category grouping.Everything tagged “Needs Review.”
Date filterA reporting or retention period.Invoices created this quarter.
Custom-field filterOrganization-specific structured values.Cost Centre equals “Sales.”

Search tips

  • Start with the most distinctive term.
  • Try the exact reference without punctuation if OCR may have split it.
  • Use filters when common words create too many results.
  • Save a useful filtered search as a Saved View.

6. Organization tools

Correspondents

Represent people or organizations connected to documents. Use one consistent name rather than variants.

Example: Use “ABC Bank” for statements and letters instead of creating “ABC,” “ABC Bank Ltd,” and “A.B.C. Bank.”

Document types

Describe what the record is. Types should be stable business categories such as Invoice, Purchase Order, Contract, Statement, Receipt, Policy, or Employee Record.

Tags

Flexible labels that may overlap categories. Good uses include status, project, department, confidentiality, and retention markers.

Matching

Matching rules help Vaultly suggest or assign metadata from document content. Automatic learning improves as correctly classified examples accumulate. Administrators should review unexpected matches before applying broad automation.

7. Storage paths

A storage path controls how archived files are named and arranged inside Vaultly-managed storage. It may use folders, fixed text, and supported placeholders derived from metadata.

  1. Choose a descriptive name.
  2. Enter a simple pattern.
  3. Use Preview with a representative document.
  4. Confirm that missing metadata does not create confusing paths.
  5. Save and apply it to a small test group first.
Example design: Organize finance documents by year, correspondent, and type so a 2026 Acme invoice has a predictable managed path. Always verify the actual placeholder syntax offered by your Vaultly version using Preview.
Important: Do not manually rename files inside Vaultly’s managed media storage. Make changes through the Vaultly interface.

9. Saved views

A Saved View preserves a useful search/filter arrangement. It provides a repeatable working queue without moving or duplicating documents.

Examples: “Unpaid invoices,” “Contracts expiring within 90 days,” “HR documents needing review,” or “Uploads with no document type.”

Give each view a task-focused name. Review shared views periodically so old business rules do not confuse users.

10. Workflows

Workflows automate repeatable actions. They consist of triggers, optional conditions, and actions.

PartMeaningExample
TriggerThe event that starts evaluation.A new document is consumed.
ConditionA rule that must match.Content contains “INVOICE” and correspondent is Acme.
ActionThe change Vaultly makes.Assign type Invoice, tag Accounts Payable, and storage path Finance.

Safe workflow rollout

  1. Write down the intended rule in plain language.
  2. Test against a few non-sensitive documents.
  3. Check for false matches.
  4. Enable the smallest necessary scope.
  5. Monitor File Tasks and recently processed documents.
A broad workflow can misclassify many documents quickly. Test conditions carefully before relying on automatic actions.

11. Email intake

Mail accounts and rules let authorized administrators import email attachments into Vaultly.

Typical setup

  1. Use a dedicated mailbox such as invoices@company.example.
  2. Connect it with the minimum required mailbox access.
  3. Create rules for sender, subject, folder, or attachment behavior.
  4. Test with one message.
  5. Review processed mail and imported documents.
Example: Import PDF attachments from approved suppliers, assign the “Email Intake” tag, and route them to a finance review queue.

Processed-mail history helps explain why a message was imported, skipped, or failed.

12. Downloading, sending, and sharing

Users with permission may download originals or archive versions. Some deployments also support email sending or temporary share links.

  • Original: the file exactly as uploaded.
  • Archive version: a normalized or OCR-enhanced version produced during processing, when available.
  • Share link: access without a normal Vaultly account, usually with an expiration. Treat it as sensitive.
Before sharing, confirm the recipient, document permissions, confidential content, and link expiration. Revoke links that are no longer required.

13. Trash

Deleting a document normally moves it to Trash first. Authorized users may restore it or remove it permanently.

Example: If an invoice is deleted accidentally, open Trash, verify the record, and restore it. Permanent deletion should follow your organization’s retention policy.

14. Personal settings

Settings generally affect the signed-in user rather than the whole deployment. Options may include appearance, language, date display, notifications, list behavior, and update preferences available to that account.

Personal settings are different from Application Configuration, which can affect everyone and is restricted to authorized administrators.

15. Users, groups, and permissions

Every person should have an individual account. Groups make permissions consistent for job roles.

PermissionAllowsExample
ViewRead or list a resource.Finance users can view invoices.
AddCreate a resource.Records staff can create tags.
ChangeEdit a resource.HR managers can update employee record metadata.
DeleteMove to trash or remove, depending on the resource.Limited to records administrators.

Global and object permissions

Global permissions grant access to a resource type. Object permissions restrict or grant access to particular documents or metadata objects. Ownership may also affect access.

Suggested small-business roles

  • Vaultly Administrator: deployment configuration, users, diagnostics, and recovery.
  • Records Manager: metadata design, workflows, and controlled deletion.
  • Department User: upload, view, and edit permitted department documents.
  • Read-only Auditor: view approved records without changing them.
Least privilege: do not make routine users administrators. Test a role using a non-admin account before onboarding a team.

16. Application configuration

Configuration options affect the deployment and are intended for trusted administrators.

OCR settings

Control language selection, OCR mode, page rotation, deskewing, image limits, and related processing behavior. Incorrect settings may reduce search quality or increase processing time.

Barcode settings

Enable supported barcode detection and document separation behavior. Test with representative scans before applying it to bulk intake.

Environment-managed settings

Some foundational settings are defined in the VM’s private .env file and require container recreation. Never place real secrets in Git or screenshots.

Example: Sinhala, Tamil, Chinese, and English OCR require the matching language identifiers and installed language packages. Change languages only after confirming deployment support.

18. Practical business examples

Accounts payable

  1. Upload or email the supplier invoice.
  2. Verify OCR, supplier, invoice date, and total.
  3. Assign Invoice and Accounts Payable metadata.
  4. Add an approval status custom field or tag.
  5. Use a Saved View for invoices awaiting approval.
  6. Mark Paid after settlement while retaining the record.

Contract renewal

  1. Upload the signed contract.
  2. Assign correspondent and Contract type.
  3. Add expiry date and responsible department custom fields.
  4. Create a Saved View for upcoming expirations.
  5. Use a workflow to tag contracts that match the department’s rule.

Employee records

  1. Create an HR group with limited permissions.
  2. Restrict employee documents to that group.
  3. Use consistent document types such as Agreement, Review, and Certificate.
  4. Never use broad public share links for sensitive HR material.

Audit request

  1. Create a read-only auditor account or group.
  2. Grant access only to the required records.
  3. Create a Saved View for the audit scope.
  4. Remove or expire access after the engagement.

19. Security, retention, and backups

  • Use strong unique passwords and individual accounts.
  • Restrict administrator access.
  • Review groups and permissions regularly.
  • Keep the Ubuntu VM, Docker Engine, and Vaultly image updated through a tested process.
  • Protect the VM-only .env file and never commit it.
  • Define retention and permanent-deletion rules.
  • Keep recoverable backups outside the VM.

What to back up

A complete recovery plan needs the PostgreSQL database, document media, application data, export/consume requirements, deployment configuration, and secrets needed to recreate the service.

A VirtualBox snapshot is useful but is not a complete backup strategy. Keep a separate backup on different storage and test restoration.

Useful VM health commands
